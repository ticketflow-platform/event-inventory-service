# Форматирование Java

Используется Spotless 8.12.0 с Eclipse formatter 4.41: основной отступ и
дополнительный отступ продолжения — по 4 пробела, длина строки — 120 символов.
Инициализаторы массивов оформляются с пробелами: `new Object[] { value }`.
Аннотации параметров методов располагаются на отдельных строках, включая `@Valid`.
Существующие пустые строки между параметрами сохраняются; форматтер не добавляет их автоматически.
Форматирование не заменяет правила разработки из `AGENTS.md`.
Нужны установленный Gradle (в проекте нет Wrapper) и JDK 26.

```powershell
gradle spotlessApply # отформатировать production-код и тесты
gradle spotlessCheck # проверить форматирование без изменений
gradle check         # форматирование, тесты и JaCoCo gate
```

`opencode.jsonc` подключает тот же Spotless для Java-файла после правок OpenCode.
Команда настроена для Windows; отдельный плагин OpenCode не нужен.

## Zed

`Ctrl+Alt+L` (`editor::Format`) использует тот же Spotless через
`scripts/format-java.ps1`. Привязка клавиш уже настроена в пользовательском keymap.
Все правила Java-форматирования задаются в `build.gradle.kts`; отдельный JDT-профиль
в Zed больше не используется. SQL-форматирование не меняется.

Адаптер передаёт текст буфера через stdin и возвращает результат через stdout:
несохранённые правки учитываются, исходный файл на диске не изменяется.
Файл должен иметь путь под `src/*/java`; форматирование выделения не поддерживается.
Запуск Gradle может занимать несколько секунд.

### Sort Members

`Alt+Enter` → **Sort Members for '…' (call order)** использует AST-сортировщик
из `scripts/java-sort`. Подключение идёт через `lsp.jdtls.settings.lsp_proxy_path`:
обёртка сохраняет штатный Java proxy и JDTLS, заменяя только действие сортировки.
Путь `lsp_proxy_path` должен быть абсолютным: относительные пути расширение Zed
разрешает от своего каталога, а не от проекта. Для другого клона укажите его путь
к `scripts/java-sort-proxy.cmd` в `.zed/settings.json`.
После первого подключения выполните в палитре Zed **editor: restart language server**.

Правила:
- Методы располагаются группами: public, protected, package-private, private.
- В каждой из первых трёх групп сохраняется исходный порядок.
- Для private выполняется обход в глубину: `first → nested → second`.
  Корни обхода — non-private методы в указанном выше порядке.
- Рекурсивные и общие private-методы включаются один раз; неиспользуемые остаются
  в конце в исходном порядке.
- Поля, конструкторы, блоки инициализации и enum-константы не переставляются.
  Вложенные классы сортируются независимо. Комментарии перемещаются вместе с методами.
- Учитываются вызовы без получателя, через `this` и имя текущего класса, включая
  method references. Вызовы на других объектах не образуют зависимостей.
- Неоднозначная перегрузка одного имени с одинаковым числом аргументов останавливает
  сортировку без правок: инструмент не угадывает типы без полноценного binding analysis.

Сортировка работает с несохранённым буфером и применяет версионированную правку
через Zed, поэтому её можно отменить `Ctrl+Z`. Она не выполняется автоматически
при форматировании. После изменения буфера во время расчёта устаревшая правка отклоняется.

Нужны Node.js в PATH, JDK с `javac` и уже установленный штатный Java proxy расширения
Zed. Используются AST-библиотеки из установленного JDTLS; новые Maven/npm-зависимости
не скачиваются. Класс инструмента компилируется в `build/java-member-order`.
Интеграция и тесты запуска на этой машине рассчитаны на Windows.

```powershell
node --test scripts/java-sort/proxy.test.mjs scripts/java-sort/sorter.test.mjs
node --test scripts/java-sort/smoke.test.mjs
```

Smoke-тест использует штатную команду запуска из лога Zed, но отдельную временную
рабочую область JDTLS. Текущий language server редактора не останавливается.

Проверка адаптера (совпадение с Gradle, несохранённые правки, UTF-8 и сохранность файла):

```powershell
gradle spotlessApply
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/test-format-java.ps1
```

## Перед коммитом

Включить hook для текущего клона (один раз):

```powershell
git config --local core.hooksPath .githooks
```

Hook запускает `gradle spotlessApply`. Если форматирование изменило Java-файлы,
коммит останавливается: проверьте diff, добавьте нужные изменения через `git add`
и повторите коммит. Hook сам ничего не добавляет в индекс.

При незастейдженных изменениях отслеживаемых Java-файлов hook останавливается
до форматирования. Сначала добавьте их в индекс или временно уберите самостоятельно:
это защищает частично подготовленные изменения от смешивания.
